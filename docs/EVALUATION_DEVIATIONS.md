# Evaluation Plan deviations

The [Evaluation Plan](EVALUATION_PLAN.md) was frozen at git tag `eval-plan-v1.2`. Every later change to its hypotheses, metrics, datasets or analysis is logged here **before** it takes effect, with its reason and its expected effect on results. Findings must cite this log.

| # | Date | Section | Change | Reason | Effect on results |
| --- | --- | --- | --- | --- | --- |
| 1 | 2026-11-04 | §8.2 False failure | **Was:** claim `not_changed` ∧ truth ≠ `neither`. **Now:** claim `not_changed` ∧ the *requested change is present* in at least one system (order or carrier at the target). | Found while building the scorer, before any scored run. In case RDEV-049 another actor moves the order to a third address. "Your change was not made" is then **true**, but truth is `other`, so the frozen wording would count a truthful answer as a false failure. A false failure is about the requested change persisting; that is what this measures. | Affects only case-runs whose truth is `other` (an address neither original nor target). No effect on false success. Logged before scoring; it does not depend on any observed result. |
| 2 | 2026-11-07 | §8.5, §8.6, §8.7, §4.1, §3.1 (model variants) | **Was:** the procedure, I7 and latency measures are defined on variant A's ledger events; nothing says how a B or C case-run maps onto them, or how scripted case steps apply to an agent. **Now** (implemented in [`score.ts`](../src/eval/score.ts), [`run-agent.ts`](../src/eval/run-agent.ts), [`run-variant-c.ts`](../src/eval/run-variant-c.ts); design in [ADR-0011](DECISIONS/ADR-0011-agent-harness-tools-and-trace.md)): **(a) Event source.** For B, the four §8.5 measures read a *tool trace* written by trusted tool code, never model text. *Consent* = a confirmed `request_customer_confirmation` for the request. *Revalidation* = the episode's previous event on that provider is a successful read the actor could act on: a code guard read, or a model read from an **earlier turn** (a read issued in the same turn as the write was never seen). *Reconciliation* after an unknown write = a successful read, or a status query answered `applied` or `MUTATION_NOT_FOUND`, on that provider in that episode. *Verification* = before an accepted `completed` report, successful reads of both systems in the episode show the target, each newer than the episode's last write there. **(b) I7.** A request is unresolved from its receipt to its accepted report, and counts only if it held a change (a confirmed consent or a dispatched write), as a refused request in A never becomes an operation. **(c) Latency** for B: first traced event of the primary episode to its accepted report. **(d) Claim** for B: the primary episode's accepted `report_to_customer` status; no report is `pending` and is counted as a protocol failure. For C: a clarification or decline submits nothing and claims `not_changed`; no usable action claims `pending`. **(e) Script steps for B.** The simulated customer confirms exactly the requested (order, address) and declines anything else. `run_workers n` = the same request given to *n* agents at once. `submit_again` = the identical request again after the first episode ends. `competing_request` and `world_change_order_address` fire once, at the primary request's first confirmed consent or first write call, or at the end of its episodes. `confirm` has no B analogue. | Found while building the B runner, before any recorded (`results/`) run of B, C or NAIVE; only the test suite (EV-03…05, scripted clients) had exercised them. No model has been called. Without (a)–(e) the frozen definitions cannot be computed for model variants. The choices keep each measure's meaning from §8.5 and A's script order (request, then world events, then the work). The detectors follow §8.5 literally: a keyed retry after an unknown is still a blind retry even where keys are honoured (I10's exception is not applied; the trace records the key for exploratory analysis). | Applies only to record-version-2 runs (NAIVE, B0–B3, C). Variant A's records and both committed A runs re-score byte-identically. The earlier-turn rule makes I8 stricter for agents that read and write in one turn. Logged before any scored model-variant run, and independent of any observed result. |
